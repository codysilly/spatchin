# C070 ATIS acquisition plan — revised draft, 2026-11-25

The owner supplied screenshots of the provider's API documentation at https://atis.info/api on 2026-11-25. This supersedes the 62-station directory-based polling proposal. The documentation identifies GET /stations (array of airport identifiers with D-ATIS), GET /all (array of all airport D-ATIS data), GET /:airport, GET /history/:airport (last 24 hours), and GET /stream (server-sent events). No live endpoint was requested to develop this change.

## Bulk snapshot
Request /stations once and /all once per execution; intersect station identifiers with the verified 130-airport C070 registry. Filter bulk reports to C070, validate source timestamps and independently retain newest combined/arrival/departure records. Retain historical reports for delisted stations without presenting runway information as current. Station-list exclusion means not configured for the current collection snapshot, not proof of permanent service absence. If either endpoint fails, responses are malformed, or valid C070 reports disagree with station list, keep the previous snapshot. No retry or per-airport fallback. Socket timeout 20 seconds, 8 MiB per response cap; existing five-minute job timeout. Synthetic flat report array fixtures follow the documented array description and existing report fields; actual response shape has not been captured. No claims of actual supported count or MEM availability until authorized collection.

Two requests per cycle instead of the current three or proposed 62. Hourly only: 48/day, versus current 72. With six fallback offsets plus hourly dispatch: nominal 336/day, versus current 504; excludes additional dispatches. Request count reduction does not prove lower transfer bytes or provider-approved rate. Existing schedules and 45-minute freshness threshold unchanged. No public redistribution terms or polling limit established by supplied documentation.

## Future SSE option
The documentation describes /stream with airports filter, replay of newer events within 24 hours using Last-Event-ID (opaque .NET ticks), 15-second keepalives, five concurrent streams per IP and HTTP 429 beyond that. First connection has no replay; use /all for initial state. A shared backend connection could improve freshness without polling; requires persistent cursor, bootstrap/reconnect race handling, deduplication, backoff, bounded cache and publication, hosting/security/cost review. Do not open streams from each browser or implement a production stream in this PR.

## Release gate
Explicit production authorization remains required for switching the collector to the documented bulk endpoints and automatic Pages publication. No new provider requests, workflow dispatch, schedule changes, costs, credentials or version increments authorized by this offline development. Verify actual /stations and /all response shape and scope on first authorized ordinary run; retain last good snapshot on failure. Preserve the provider's warning against real-world flight planning or navigation.
