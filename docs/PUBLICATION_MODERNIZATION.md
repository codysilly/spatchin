## Candidate architecture

Keep GitHub Pages and same-origin data URLs. Use GitHub for application source; replace recurring snapshot commits with a private authenticated publication relay. Candidate: Cloudflare Workers Free + SQLite-backed Durable Object. Store latest/prior per source and pending/accepted/previous complete sets. Only public projections enter the relay. The private Windows NOTAM state and ledger stay separate. The diagrams catalog and script are pinned code assets; the candidate allowlist has 22 files. The existing production allowlist is untouched.

Publish on data-ready signals with coalescing near the 10-minute acquisition cycle. A publication-only watchdog may recover missed signals; it must not run a collector. Serialize stage/deploy/verify/reconcile. Use code SHA, exact file list, source timestamps, digests and immutable candidate artifact. Retain independent last-good data for failed sources. No rollback of source time in normal operation; code rollback uses latest verified data. Do not mark stale data fresh. Reject unknown source, future/older data, same timestamp with different bytes, malformed data, digest mismatch, links, missing or extra files. Verify public manifest AND referenced file bytes before accepting a release. On uncertain deployment retain pending; reconcile actual deployment evidence before clearing or accepting. Never trigger provider requests from publication recovery. The local file relay models atomic replacement under a single-writer contract, not distributed locking; the SQLite model tests transactional ordering and restart persistence only.

Cloudflare Free limits (Nov 28 docs): 5 GB total SQL storage, 1 GB/object per FAQ, 100k rows written/day, 5m read/day, 100k requests/day, 13k GB-s/day. Approximately 33 MB raw for five sets at current sizes; 512 KiB chunks. Free plan fails at limits; verify actual plan, quotas, CPU, row accounting, auth and transfer in synthetic cloud staging before cutover. GitHub custom Pages Actions bypass the branch-based soft 10 builds/hour limit; verify queue/delivery latency. Artifacts expire (Pages upload default one day); durable accepted checkpoint and independent backup are required. KV eventual consistency, release assets, R2 potential overages and public raw GitHub URLs are not preferred. No new resource is provisioned by this code.

Browser: poll a small manifest every two minutes, fetch changed snapshots only, verify digest and retain last good on mismatch. Test CDN cache and mixed releases; current NOTAM reader rejects older/conflicting data. Do not assume cross-file atomicity at CDN. A proposed 20-minute NOTAM age threshold requires separate schema/UI implementation (current AGE_LIMIT is hours) and approval before deployment. Measure acquisition-to-public visibility, not just workflow duration. At 508353 bytes, a full download every two minutes is ~11 GB per continuously open browser per 30 days; GitHub Pages soft bandwidth is 100 GB/month. Preserve existing source-specific freshness semantics and raw NOTAM scope/coverage warnings.
